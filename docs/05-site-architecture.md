# Stone Village — архітектура сайту

Чинна редакція: 28 вересня 2026. [Поточні рішення](00-current-state.md) мають пріоритет над історичними планами.

## Принцип
Бажання → розуміння середовища → вибір формату → докази → перегляд.
Це логіка розповіді, не жорсткий шаблон. Порядок, об’єднання секцій і візуальний ритм можна покращувати в межах запиту, не додаючи дубльованих тем.

## Ролі сторінок
- Головна — містечко, його переваги, відмінності двох форматів і запис на перегляд.
- /duplex-185/ — сімейне зонування, кабінет, тераса, ділянка, поверхи, характеристики дуплекса.
- /cottage-228/ — окремий будинок, приватна територія, поверхи, критий паркінг, особливості котеджу.
- Подяка — можливий елемент майбутнього сценарію реального надсилання, не поточне завдання.

## Головна: тема кожної частини
Актуальна послідовність секцій, їхні id та ролі — у таблиці [00-current-state.md](00-current-state.md#структура-головної). Кожна тема має одне основне місце; факти не дублюються між секціями, крім функціональних повторів у меню, формі й назвах продуктів.

## Продуктові сторінки
Власний перший екран → ключові факти → сценарій життя → планування поверхів → доречні характеристики → перегляд → інший формат.
Це змістова основа, не вимога ідентичної верстки. Дуплекс показує сімейний простір і кабінет; котедж — незалежність та більшу приватну територію. Загальну інфраструктуру й маршрути не копіювати повністю: дати доречне посилання на головну.

## CTA й мобільна композиція
Primary CTA — «Записатись на перегляд». Форма описана в [11-conversion.md](11-conversion.md).
Планування на продуктових сторінках доступне перемиканням поверхів. Меню внутрішніх сторінок веде до відповідних секцій головної.
Mobile має власне кадрування, порядок і щільність. Гортання має бути очевидним, елементи — зручними для дотику. Не компенсувати слабку композицію однаковими картками чи великими порожніми відступами.
